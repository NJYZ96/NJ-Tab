# NJ-Tab 4.2 需求文档（2026-11-18 定稿）

本稿汇总 4.1 交付后、用户试用期间在对话中陆续提出的全部新需求，即 4.2 版本的开发依据。执行顺序（用户 2026-11-18 定）：先给 4.1 打包发布 GitHub Release 并写更新日志，发布完再按本稿开发 4.2——4.1.0 Release 已于 2026-11-18 发布完成。本稿已经全文审查（只有关于密码、令牌的要求文字，没有任何实际的密码、令牌、密钥值），并上传 GitHub 仓库「需求文档」目录存档。

**共同红线**：标签数据绝不能丢；数据格式只加新字段、不改旧字段；改的只是 UI 排布和行为，原本有的功能一个不能少（盘点清单见文末）；密码、令牌永不进入任何备份、导出、Gist 和日志。

---

## 需求一：顶部功能行与菜单结构

### 现在的问题

1. 菜单混乱、功能藏得深：功能入口和状态信息混排，“查看配置、导入、导出、日志”全塞在“其他功能”下拉里，找 WebDAV 要点三层。
2. 中间宽度（约 880px）时菜单折成多行，把搜索框和页面顶部内容挡住；很宽、很窄时反而正常。

### 布局（参考 OneTab 顶栏，用户附了截图定的方向）

1. **一整行独立的功能行**：左边品牌（NJ-Tab），**中间是搜索框**（宽度可伸缩），右边是菜单入口（小字，可排两行）。
2. 功能行在页面正常排版里实占一行，下面才是标签组列表，从结构上永不遮挡任何内容；中间宽度靠搜索框伸缩 + 右侧两行小字消化，不折行。
3. **不用三条线折叠按钮**（用户明确否决）。
4. 每个菜单入口都有自己的**二级页面，在当前页整页打开**（不是新开浏览器标签页），相关的配置和按钮都收进各自页面，不再散落。

### 状态信息（功能行里的小字）

- “已存 X 组”：悬停显示**总条数**；点进回收站后，这块改为显示回收站的组数，悬停显示回收站总条数。
- “已用空间”：悬停显示**占用百分比**。注：界面上现有的“/ 10mb”是原项目遗留文案——Chrome 默认上限确为 10MB，但本插件带“不限制存储”权限、实际不受此限；百分比以 10MB 为参考分母并注明参考值，新版去掉误导写法。

### 各二级页面的内容

- **首页 / 回收站**：标签组列表（回收站可恢复、彻底删除），无配置。
- **Gist 备份页**：推送、拉取按钮；GitHub Token、Gitee Token（凭据放本页，和 WebDAV 密码放 WebDAV 页一个道理）；自动备份开关与频率设置（见需求三）。
- **WebDAV 备份页**：服务器地址、账号、密码；**连接测试按钮**（见需求三）；上传备份；恢复（见需求三的版本列表）；自动备份开关与间隔、保留规则（见需求三）。
- **导入与导出页**：导入、导出合并为一个入口，一页办完；导入的两种格式（默认格式、OneTab 格式）都收进本页。
- **配置页**：原“查看配置”**改名就叫“配置”**。所有开关类设置统一收进来，包括原先藏在菜单里的拖拽标签组、拖拽标签开关，以及原配置页各项（发送后打开后台页、休眠打开等）。
- **日志页**：日志列表 + 日志清理设置（见需求四）。

### 配置自动保存（全局规矩）

所有页面的配置改完**自动保存**，不再需要手动点“保存配置”；保存后给一个轻提示（如“已保存”小字），原保存按钮去掉。

## 需求二：主题切换改成单按钮轮换

- 现在是下拉菜单选择，改成**一个按钮**，放在功能行里。
- 每点一次轮换一档：**白天 → 晚上 → 自动 → 白天**……循环。
- 按钮用**太阳 / 月亮 / 日月结合的图标**表示当前档位，**不要文字形式**。
- **默认档位是“自动”**（首次安装、重置后都默认自动）。
- 选好的档位照旧记住；“自动”照旧跟随系统昼夜。

## 需求三：备份规则（文件名、内容、频率、WebDAV 增强）

### 文件名统一改版

- 现在：本地导出的备份文件名只到日期，如 `njtab-backup-20261118.json`（用户实测，代码核实）；WebDAV 的版本文件名到秒。
- 改成：**`NJ-Tab-Backup-20261118-053045.json`**——前缀用 NJ-Tab-Backup 这种大写驼峰写法，**时间戳精确到秒**（年月日-时分秒）。精确到秒是为了防止重名互相覆盖（用户先前说精确到分钟，本次改为到秒，以本次为准）。
- 适用范围：本地导出的备份文件、导出的网页单文件（后缀 .html）、WebDAV 备份文件，三者同一套命名。
- 用户确认：服务器上目前不存在旧名备份，**不需要兼容旧文件名**，新版只认新名即可。

### 备份内容包含全部配置

- **所有备份**（本地导出、WebDAV、Gist）除了标签数据，还要**包含插件的配置**（主题、各开关、备份的间隔与保留规则等设置），恢复时配置一并恢复。
- **除外项（用户 2026-11-18 明确）**：**WebDAV 的地址、账号、密码整组连接信息都不进备份**；GitHub / Gitee 令牌也不进备份（沿用现有规矩）。也就是说换一台电脑恢复后，WebDAV 连接和令牌要重新填一次，其余设置都能跟回来。
- 唯一例外：导出的**网页单文件**不带配置，它只是给人看的标签清单。

### Gist 自动备份频率（用户拍板定版）

- 原版做法（已查实）：Gitee 每 70 分钟、GitHub 每 90 分钟后台自动推送，4.1 原样保留、无可调设置。
- 新版在 Gist 页做成可调：**5 个档位——5 分钟 / 15 分钟 / 30 分钟（默认）/ 1 小时 / 2 小时**，最短 5 分钟、最长 2 小时。
- 依据：GitHub 官方上限为带令牌 5000 次/小时、产生内容 500 次/小时，备份一次只用 2~3 次请求，最短档也离上限很远；Gitee 官方未公开数字、管得严些，但这个量也远低于社区经验的每分钟 30 次。
- 选到短档位时，页面给一行文字提醒：频率太短可能会被平台限流。
- **被限流报错必须记进日志**（哪家平台、限流错误、时间）。
- 数据自上次成功备份后**没有变化时跳过**这次自动备份：Gist 页状态处给一行文字提示（如“数据无变化，已跳过”），日志也记一条。

### WebDAV 增强

1. **连接测试**：WebDAV 页加“测试连接”按钮，用当前填的地址、账号、密码试连一次，当场告诉用户连得上还是连不上、失败原因，避免地址或密码输错了到备份时才发现。
2. **自动备份间隔默认 12 小时**（4.1 现在是 24 小时，本次改默认），可以自定义；保留规则（最近 N 天 / 最近 N 份）不变。
3. **恢复时列出全部版本并可删除**：点“从 WebDAV 恢复”后，列出服务器上**全部多版本备份**（每条要显示**文件名、时间、文件大小**），用户选一个恢复；每个版本旁边要有**删除**操作，能手动删掉某个不要的版本（删之前要确认，删完刷新列表）。恢复原有的安全流程不变（先强制备份当前数据、两步确认）。

## 需求四：日志功能增强

- 现状：只记了推送成功与否，太少，不好排查。
- **记录范围补全**：Gist 推送 / 拉取、WebDAV 上传 / 恢复、导入、导出、自动备份（含跳过、含被限流）、回收站自动清理、恢复前强制备份、数据转换等关键动作，每条带时间、动作、成功还是失败、失败的简短原因。
- **自动清理**：做清理开关（可开可关），可按“只保留最近多少天”或“只保留最近多少条”清理；momo 建议默认开、保留 30 天且最多 500 条。设置放在日志页里。
- 日志里绝不出现密码、令牌原文（沿用现有规矩）。

---

## 需求五：鼠标中键点击标签，后台打开

- 现状（已查代码确认）：列表条目是普通文字元素冒充链接、只监听左键，中键点上去浏览器不认，只冒出自动滚动图标，不打开页面。
- 改成：**中键点击任意标签条目，在新标签页后台打开**（不跳过去，与左键效果一致），并拦住浏览器的自动滚动。
- 范围：主列表、回收站、搜索结果三处；左键行为保持不变。
- **中键打开永不删除此条标签**。配置里现有的那条开关（现文案“打开标签并将其从标签列表中删除（当标签组锁定时，不会删除）”）**只对鼠标左键生效**，管的是左键点击打开时删不删；并且这条开关的**文案要改得更精确**，写明是“左键点击打开时删除此条”，免得以为对中键也有效。
