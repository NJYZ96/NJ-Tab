# NJ-Tab 4.6.4 需求/修复清单

修订时间：2026-11-21 09:57:00（北京时间）
修订版本：v2.1

说明：本清单是南极验收 4.6.3 期间陆续提出的小问题。2026-11-21 09:11 南极指示：不等 4.6.3 审完，4.6.4 直接开发，与 4.6.3 一起审核；审核报告与 4.6.3 的合并成一份。本清单定版 v2.0 共 9 条；v2.1 补记：南极实测 4.6.4 后顶栏与令牌行版式有实测问题（见 4.6.4-2、4.6.4-7 补记），并新增 4.6.4-10。

4.6.4-1　确认框文案排版

来源/现象：拉取确认框现在的文案挤成一团：警告、内容构成连在一起；「这是最后确认：请输入字母 Y，确认按钮才会生效。」单独占一行在输入框上方，不美观（南极 2026-11-21 08:31 提出）。

方案/原因：拉取确认框前两句按南极 2026-11-21 08:44 给的原文改：第一句「拉取会用远端 Gist 上的备份，覆盖本地的所有配置、全部标签和回收站内容。」第二句「本地现在的所有内容（不包含密码令牌等敏感信息）将被替换，确定要拉取吗？」确认框正文改成一句话一行、每行之间空一行；「这是最后确认……」那句不再单独成行，改成输 Y 输入框里的背景提示文字（占位文字，框里没输入时淡淡显示）。所有共用这个确认框的操作（拉取、推送、导入完整备份、WebDAV 恢复、删除全部备份）统一生效。

验收：打开任意一个要输 Y 的确认框：正文每句一行、行间有空行；输入框未输入时显示背景提示文字；输 Y 后确认按钮生效的行为不变。

4.6.4-2　菜单栏与状态信息排版

来源/现象：现在的菜单分两行（第二行是配置加状态），状态还会被挤掉行，南极 2026-11-21 08:46 指出本条之前写得不对；08:49 南极给出明确排法。

方案/原因：按南极 08:49 的排法：菜单只占第一行，顺序为：首页、回收站、Gist、WebDAV、导入/导出、配置、日志、主题图标（主题图标在最末）。状态信息独占第二行，左边缘与「首页」对齐。（菜单名按 4.6.4-5 的改名：Gist、日志。）

验收：打开工作台：第一行菜单顺序与上面一致；第二行只有状态信息，左边缘与「首页」对齐；状态数字变长变短不影响菜单排版。

补记（2026-11-21 09:37 南极实测 4.6.4 后修订）：菜单栏和状态信息应固定在顶栏右边，中间搜索框伸缩自适应宽度；菜单作为基准，状态信息始终与「首页」左对齐。实测菜单没靠右、搜索框没伸缩，原因是改品牌区时把 nj-brand-wrap 的收尾标签弄丢了、顶栏结构被打乱，须修复并用真实浏览器渲染核对。

4.6.4-3　品牌区排版

来源/现象：现在仓库图标在品牌列的右边单独占一列（南极 2026-11-21 截图），排版不美观。

方案/原因：品牌区总共两行：第一行是品牌名「NJ-Tab」；第二行是仓库图标加版本号（图标在版本号前面）；两行左边缘对齐。

验收：看顶栏左上角：第一行 NJ-Tab，第二行 GitHub 图标紧挨着版本号，两行左边缘对齐。

4.6.4-4　返回顶部改上下双箭头

来源/现象：现在右下角是「回到顶部」文字按钮，南极 2026-11-21 08:32 要求换成图标样式。

方案/原因：右下角固定两个圆形箭头按钮、上下排列：上箭头回到顶部，下箭头去到底部；去掉原来的文字按钮。只出现在首页、搜索页、日志页、回收站页；其他页面（配置、同步等页面）不显示（南极 2026-11-21 08:44 修订，原口径只含首页、搜索页）。

验收：首页、搜索页、日志页、回收站页右下角有上下两个箭头按钮：点上箭头回到页面顶部，点下箭头去到页面底部；切到配置、同步等其他页面时两个箭头不显示。

4.6.4-5　菜单改名

来源/现象：南极 2026-11-21 08:38 提出：菜单名再精简。

方案/原因：「查看日志」改名为「日志」；「Gist 备份」改名为「Gist」。

验收：顶栏菜单里显示「日志」「Gist」，其他菜单名不变。

4.6.4-6　WebDAV 配置页表单对齐

来源/现象：南极 2026-11-21 08:55 发来 WebDAV 配置页截图：名称和输入框隔得太远；密码下面的提示句顶着页面左边缘、没和输入框对齐；「连接测试」自己一行、「上传备份到 WebDAV / 从 WebDAV 恢复」另一行，按钮没排齐。

方案/原因：名称列收窄并固定宽度，所有输入框左边缘一条线对齐；密码下面的提示句挪到与输入框相同的左边缘（缩进对齐）；「连接测试」「上传备份到 WebDAV」「从 WebDAV 恢复」三个按钮放同一行，连接测试的结果提示固定显示在按钮的下一行。

验收：打开 WebDAV 配置页：名称与输入框距离明显变近、所有输入框左边缘对齐；密码提示与密码输入框左边缘对齐；三个按钮同一行，点连接测试后结果出现在按钮下一行。

4.6.4-7　Gist 推送拉取按钮跟到对应输入框后面

来源/现象：南极 2026-11-21 09:00 发来配置页备份功能截图并提出：现在推送、拉取 4 个按钮单独排在下面一行，离对应的令牌输入框太远。

方案/原因：「推送到 GitHub 的 Gist」「从 GitHub 的 Gist 拉取」两个按钮放到 GitHub Token 输入框后面同一行；「推送到 Gitee 的 Gist」「从 Gitee 的 Gist 拉取」放到 Gitee Token 输入框后面同一行；取消原来单独一行的 4 个按钮。4 个按钮大小一致（等宽等高、文字居中），上下两行也对齐成列（南极 2026-11-21 09:01 指出第一版模板按钮大小没对齐）。令牌下方的加密保存提示按 4.6.4-6 的规矩与输入框左边缘对齐（原「已保存，留空表示不修改」提示语已按 4.6.4-9 删除）。

验收：打开配置页备份功能区：每个令牌输入框后面同一行跟着它自己的推送、拉取按钮；页面下方不再有单独一行的 4 个按钮。

补记（2026-11-21 09:37 南极实测 4.6.4 后修订）：实测令牌输入框和推送按钮之间隔了大段空白——输入框实际宽度与外层格子对不上，须收紧到按钮紧跟输入框，并用真实浏览器渲染核对。另（09:47 南极定）：行抬头改为「GitHub 仓库令牌：」「Gitee 仓库令牌：」；按钮文字去掉仓库名，统一为「推送到 Gist」「从 Gist 拉取」（抬头已有仓库名，按钮不重复）。另（09:50 南极定）：两个抬头要两端对齐（09:53–09:56 南极两次纠正：英文单词绝不能拆开——名字占一样宽的格子，差的宽度留在英文与中文之间的空里，使两行左头右尾都齐、「仓库令牌：」同列开始）；密码与令牌的那两句提示语固定两行、不许折行（Gist 页与 WebDAV 页同此规矩）。

4.6.4-8　没填令牌的仓库自动推送假成功

来源/现象：南极 2026-11-21 09:03 实测：只填了一个仓库（Gitee）的令牌、开启自动备份后，没填令牌的 GitHub 也记了一条「自动推送到 GitHub · 成功」（绿色）；展开详情却是「GitHub token 没有保存 / 0 秒等待 / 任务结束」——根本没推送，却报成功。

方案/原因：已查清根因：后台自动推送查到令牌没保存就直接结束任务，步骤里没写任何「失败」字样；而日志列表判断成功失败的方法是「步骤里没出现失败二字就算成功」，于是这种半路退出被误判成成功。修法：没保存令牌（或没保存 Gist 编号）的仓库，自动推送直接跳过，日志记一条「已跳过：令牌没有保存」并显示灰色「已跳过」状态（不算成功、也不算失败）；同时后台写日志时带上明确结果，不再靠猜。Gitee、GitHub 两边同修。

验收：只填一个仓库令牌、开启自动备份：到点后，有令牌的仓库正常推送记成功；没令牌的仓库记「已跳过」、灰色，不再出现绿色成功。

4.6.4-9　删掉「已保存，留空表示不修改」提示语

来源/现象：南极 2026-11-21 09:14 提出：令牌输入框下面那句「已保存，留空表示不修改」删掉。

方案/原因：删掉两个令牌输入框下面的这句提示；输入框里本来就显示打码的令牌，一眼能看出已保存。WebDAV 密码框已保存时原来也用这句话当占位文字，一并改成圆点显示，不再出现这句话。

验收：打开 Gist 页和 WebDAV 页：任何地方都不再出现「已保存，留空表示不修改」这句话；已保存的令牌仍显示打码样子，密码框显示圆点。

4.6.4-10　自动备份状态移到对应推送拉取按钮旁边

来源/现象：南极 2026-11-21 09:37 实测 4.6.4 后提出：自动备份状态不要放在下面「Gist 自动备份」区里，要移到对应仓库的推送、拉取按钮旁边、同一行；「自动备份状态」几个字不要，直接写后面的状态信息。

方案/原因：GitHub 那行在拉取按钮后面直接跟 GitHub 的自动备份状态（如「自动备份成功（时间）」「还没有自动备份记录」，状态文字不带「上次」二字），Gitee 同理；每个仓库的相关功能必须放在同一行、不换行；下面自动备份区里的两行状态删掉，只留开关和频率。

验收：打开 Gist 页：每个仓库的按钮后面同一行能看到它自己的自动备份状态，没有「自动备份状态」字样；下面的自动备份区不再有状态行。
