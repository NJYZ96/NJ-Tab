# NJ-Tab 4.6 需求/修复清单（2026-11-21）

> 本清单按南极发来的顺序逐条排列，不分类。每条依次写来源/现象、方案/原因、验收。

---

**4.6-1　取消「休眠打开」功能**

来源/现象：这个功能始终失效，4.5 审核时实测打开整组从来不休眠。

方案/原因：直接取消，去掉相关的全部逻辑、代码和文案，不再留开关和设置项。

验收：插件里再找不到「休眠打开」相关的开关、文案和设置；打开标签组恢复成普通打开，不受影响。

---

**4.6-2　令牌后 3 位显示修复**

来源/现象：保存令牌后，输入框提示显示成「末3」字样，看不到真实的后 3 位。

方案/原因：提示改为「已保存，留空表示不修改，令牌后 3 位（xyz）」，其中 xyz 换成令牌真实的最后 3 个字符；GitHub、Gitee 两处都改。

验收：保存令牌后，GitHub、Gitee 两处提示都显示「令牌后 3 位（xyz）」，且 xyz 与令牌真实的最后 3 个字符一致。

---

**4.6-3　导入/导出日志标题与详情分开、导入只留一条**

来源/现象：导出日志的标题和详情重复；一次导入会出现两条日志（一条成功、一条失败），看着乱。

方案/原因：日志标题只写状态，组数、条数放到详情里点开看；每次导入合并成一条日志，有失败时标题标「部分失败 · 共失败 N 条」，详情写导入与回收站的组数条数、去重跳过数，失败原因逐行列在后面；导出网页文件同样补上详情。

验收：导出完整备份、导出网页文件后，日志标题只有状态、点开才有组数条数；导入一次只出现一条日志，部分失败时标题带失败条数、点开明细齐全。

---

**4.6-4　Gist 手动推送日志去重**

来源/现象：手动推送后日志里出现两条（「手动推送到 GitHub · 成功」和「Gist 推送 · 成功 · GitHub」），4.5 已要求去重但仍在出现，Gitee 同样。

方案/原因：从代码层面排查日志去重为什么没认出这两条是同一件事，修好后同一动作只留带详情的一条；手动拉取同理。

验收：手动推送、手动拉取 GitHub 和 Gitee 后，日志里同一动作只剩一条带详情的记录。

---

**4.6-5　搜索框提示只留「搜索框」**

来源/现象：4.5 做了提示字号自适应，窗口拉窄时提示文字还是被截断、只剩一半。

方案/原因：提示文字只保留「搜索框」3 个字；字号自适应的需求取消，相关样式删掉。

验收：任意窗口宽度下，搜索框提示都完整显示「搜索框」，不再被截断。

---

**4.6-6　分页当前页高亮、跳页框改回车输入**

来源/现象：暗黑模式下跳页后当前页不明显、看不出在哪一页；主页跳页框是数字上下箭头的形式，无法输入也无法选择；搜索页和回收站的跳页框也有上下箭头。

方案/原因：当前页加上明显高亮，暗黑模式下也醒目；三处跳页框都取消上下箭头、改成普通输入框，输入页码按回车跳页。

验收：暗黑模式下当前页一眼能认出；三处跳页框都没有上下箭头，输入页码按回车能跳页。

---

**4.6-7　导入完整备份流程改版**

来源/现象：原急修要求导入后保留文件名，实测不合适：导入完页面刷新后，文件名还一直留在那里。

方案/原因：不再保留文件名。按钮改名「导入完整备份」；点它选好文件后，显示文件名、旁边出现「确认导入」按钮；点确认导入要过 2 次确认；导入成功后把文件名清掉。

验收：按顺序走一遍：按钮是「导入完整备份」→ 选文件后出现文件名和「确认导入」→ 两次确认后才导入 → 成功后文件名消失；刷新页面后文件名也不再恢复。

---

**4.6-8　自动备份假成功修复**

来源/现象：填了两个仓库令牌、从 Gitee 拉了 3.1 旧版数据后开自动推送，Gitee 自动备份实际没成功（自动备份状态没有记录、仓库里没有新版片段），日志却显示成功；手动推送一次以后才恢复正常。怀疑 GitHub 也有同样问题，只是被提前手动推送掩盖了。

方案/原因：从代码层面对比自动路径和手动路径的差别：怀疑自动路径在本地编号是旧版或没编号时，没有走「找新版 Gist、找不到就新建」这一步就直接结束了；GitHub、Gitee 一并排查修复。

验收：两个仓库令牌填好、本地编号还是旧版或没编号时，不手动推送、直接等自动备份触发：自动备份状态出现真实记录，对应仓库多出一个描述为 NJ-Tab 的新版 Gist 并写入最新数据；故意填错令牌时，自动备份显示失败、不再报成功。
